# XOR Advanced - Stream Ciphers

Moving beyond basic XOR operations to real cipher constructions.

---

## Single-Byte XOR

The simplest XOR cipher uses a single byte as the key. Every byte of plaintext is XOR-ed with the same key byte.

There are only 256 possible keys (0x00 to 0xFF). An attacker can brute-force all of them in microseconds. Additionally, since every occurrence of the same plaintext byte produces the same ciphertext byte, frequency distributions are preserved. This makes statistical analysis trivial.

---

## Multi-Byte XOR (Repeating Key)

A longer key is repeated cyclically to match the plaintext length. For each plaintext byte at position i, the cipher XOR-s it with key[i % key_length]. The key wraps around after reaching its end.

This is essentially a polyalphabetic cipher (like Vigenere) operating on bytes instead of letters. It provides more key space than single-byte XOR, but the repeating pattern creates a fatal weakness.

---

## Why XOR Alone Is Not Secure

### The Repeating Pattern Problem

If the key length is L, then every L-th byte is encrypted with the same key byte. Bytes at positions 0, L, 2L, 3L all use key[0]. Bytes at positions 1, L+1, 2L+1 all use key[1]. Each group is effectively a single-byte XOR cipher, which is trivially breakable.

### No Diffusion

XOR operates on each byte independently. Changing one byte of the key only affects the bytes encrypted with that key byte. There is no avalanche effect, no diffusion, no confusion beyond the XOR itself. Modern ciphers like AES combine XOR with substitution, permutation, and mixing operations to achieve real security.

### Key Reuse Is Catastrophic

If the same key is used twice (a "two-time pad"), the key cancels out entirely. Given C1 = P1 XOR K and C2 = P2 XOR K, then C1 XOR C2 = P1 XOR P2. The attacker now has the XOR of two plaintexts, from which both can often be recovered using statistical methods.

---

## Known Plaintext Attacks

If an attacker knows (or can guess) any portion of the plaintext, they can recover the corresponding portion of the key by XOR-ing the known plaintext with the ciphertext. Since the key repeats, recovering a single period of the key is enough to decrypt the entire message.

Common sources of known plaintext include file headers (PDF, PNG, ZIP all have predictable first bytes), protocol headers, and common phrases in natural language text.

## Frequency Analysis on XOR

### Breaking Single-Byte XOR

Try all 256 possible key bytes. For each candidate, decrypt the ciphertext and score the result by how closely it resembles English text. The most common byte in English text is space (0x20), followed by the letter 'e' (0x65). The key byte that produces the most English-like output is almost certainly correct.

### Breaking Repeating-Key XOR

Step 1: Determine the key length. Use the Hamming distance method: for each candidate key length, take blocks of that size from the ciphertext and compute the normalized Hamming distance (number of differing bits divided by block size). The correct key length produces the lowest normalized distance, because at the correct shift you are comparing plaintext-vs-plaintext patterns rather than random data.

Step 2: Split the ciphertext into groups. Group together all bytes encrypted with the same key byte (every L-th byte, where L is the key length).

Step 3: Break each group independently. Each group is a single-byte XOR cipher. Apply the frequency analysis attack from above to each group to recover each key byte.

Step 4: Reconstruct the full key by combining the individual key bytes.

## One-Time Pad

The one-time pad uses a truly random key that is as long as the message, truly random (not pseudorandom), and used only once. Claude Shannon proved in 1949 that this provides perfect secrecy: the ciphertext reveals absolutely no information about the plaintext.

The one-time pad is impractical for most uses because key distribution requires a secure channel as large as the message, keys cannot be reused, and generating true randomness at scale is difficult.

---

## XOR in Modern Cryptography

Despite the weakness of simple XOR ciphers, XOR is fundamental to modern cryptography. AES-CTR mode XOR-s plaintext with a keystream generated by encrypting a counter. ChaCha20 generates a keystream using XOR, addition, and rotation. CBC, OFB, and CFB modes all use XOR to combine plaintext with cipher output.

The lesson: XOR alone is not encryption. XOR combined with a properly generated keystream is the foundation of modern symmetric cryptography.
