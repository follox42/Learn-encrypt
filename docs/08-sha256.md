# SHA-256 - Secure Hash Algorithm

Part of the SHA-2 family designed by the NSA, published in 2001. SHA-256 produces a 256-bit (32-byte) hash and remains secure and widely used today.

---

## The SHA-2 Family

SHA-2 is not a single algorithm but a family of hash functions with different output sizes:

- **SHA-224**: 224-bit output (truncated SHA-256)
- **SHA-256**: 256-bit output (most widely used)
- **SHA-384**: 384-bit output (truncated SHA-512)
- **SHA-512**: 512-bit output (uses 64-bit words, 1024-bit blocks)

All share the same fundamental design but differ in word sizes, number of rounds, and internal constants. This module focuses on SHA-256.

---

## SHA-256 Overview

- **Output**: 256 bits = 32 bytes = 64 hex characters
- **Block size**: 512 bits = 64 bytes
- **Word size**: 32 bits
- **Construction**: Merkle-Damgard (same framework as MD5)
- **Rounds**: 64 rounds per block
- **Status**: Secure. No practical attacks found.

```
SHA-256("abc") = ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad
```

---

## Merkle-Damgard Construction

Like MD5, SHA-256 processes messages block by block using the Merkle-Damgard construction. The same principle applies: pad the message, split into blocks, and process each block through a compression function that updates the running state.

```
1. Pad the message to a multiple of 512 bits
2. Split into 512-bit blocks
3. Initialize 8 hash state words (H0 through H7)
4. For each block:
   a. Expand the 16 message words into 64 words (message schedule)
   b. Run 64 rounds of the compression function
   c. Add the result to the running hash state
5. Final hash = concatenation of H0 through H7
```

```
          Block 1          Block 2          Block 3
             |                |                |
             v                v                v
 IV -> [Compress] -> H1 -> [Compress] -> H2 -> [Compress] -> Final Hash
```

The key differences from MD5: SHA-256 uses 8 state words (not 4), has 64 individual rounds (not 4 groups of 16), uses big-endian byte order, and employs more complex operations.

---

## Step 1: Message Padding

SHA-256 padding follows the same principle as MD5 but uses **big-endian** byte order for the length field.

```
1. Append a single '1' bit (0x80 byte)
2. Append '0' bits until message length = 448 mod 512
3. Append the original message length as a 64-bit big-endian integer
```

The same block boundary rules apply: if the message is too long to fit the padding and length in the current block (56 or more bytes used), an extra block is needed.

### Example: Padding "abc" (3 bytes = 24 bits)

```
Original:   61 62 63
Add 0x80:   61 62 63 80
Add zeros:  61 62 63 80 00 00 00 ... 00   (pad to byte 56)
Add length: 61 62 63 80 00 ... 00 00 00 00 00 00 00 00 18
                                                         ^^
                                          24 in big-endian (0x18)

Total: 64 bytes = 512 bits = 1 block
```

**Key difference from MD5**: The length field is big-endian (most significant byte first), and message words are also interpreted as big-endian.

---

## Step 2: Initial Hash Values

SHA-256 starts with 8 initial hash values. These are the first 32 bits of the fractional parts of the square roots of the first 8 prime numbers (2, 3, 5, 7, 11, 13, 17, 19):

```
H0 = 0x6a09e667    (from sqrt(2))
H1 = 0xbb67ae85    (from sqrt(3))
H2 = 0x3c6ef372    (from sqrt(5))
H3 = 0xa54ff53a    (from sqrt(7))
H4 = 0x510e527f    (from sqrt(11))
H5 = 0x9b05688c    (from sqrt(13))
H6 = 0x1f83d9ab    (from sqrt(17))
H7 = 0x5be0cd19    (from sqrt(19))
```

These are not arbitrary. They come from an explicit mathematical formula, which ensures there are no hidden backdoors. This is called "nothing-up-my-sleeve numbers" -- the derivation is transparent and verifiable.

---

## Step 3: Round Constants

SHA-256 uses 64 round constants, K[0] through K[63]. These are the first 32 bits of the fractional parts of the cube roots of the first 64 prime numbers (2, 3, 5, ..., 311):

```
K[0]  = 0x428a2f98    (from cbrt(2))
K[1]  = 0x71374491    (from cbrt(3))
K[2]  = 0xb5c0fbcf    (from cbrt(5))
K[3]  = 0xe9b5dba5    (from cbrt(7))
...
K[63] = 0xc67178f2    (from cbrt(311))
```

Like the initial hash values, these constants are derived from a transparent mathematical process that anyone can verify.

---

## Step 4: The Six Logical Functions

SHA-256 uses six core bitwise operations on 32-bit words. This is more than MD5's four auxiliary functions.

### Right Rotate (ROTR) and Right Shift (SHR)

```
ROTR(x, n) = (x >> n) | (x << (32 - n))    Bits wrap around
SHR(x, n)  = x >> n                          Bits are lost
```

### Choice (Ch)

```
Ch(x, y, z) = (x AND y) XOR (NOT x AND z)

For each bit: if x is 1, take from y; if x is 0, take from z.
The x input "chooses" between y and z.
```

### Majority (Maj)

```
Maj(x, y, z) = (x AND y) XOR (x AND z) XOR (y AND z)

For each bit: output the majority value (whichever appears 2 or 3 times among x, y, z).
```

### Big Sigma Functions (used in the compression rounds)

```
Sigma0(x) = ROTR(x, 2) XOR ROTR(x, 13) XOR ROTR(x, 22)
Sigma1(x) = ROTR(x, 6) XOR ROTR(x, 11) XOR ROTR(x, 25)
```

### Small Sigma Functions (used in the message schedule)

```
sigma0(x) = ROTR(x, 7)  XOR ROTR(x, 18) XOR SHR(x, 3)
sigma1(x) = ROTR(x, 17) XOR ROTR(x, 19) XOR SHR(x, 10)
```

Note the difference: Big Sigma uses only rotations, while small sigma uses two rotations and one shift (bits are lost in the shift).

---

## Step 5: Message Schedule

Each 512-bit block contains 16 words of 32 bits (big-endian). The message schedule expands these 16 words into 64 words, ensuring that every bit of the original message influences the entire computation:

```
W[0]  to W[15]:  Directly from the message block (big-endian)

W[16] to W[63]:  Computed from previous words:
  W[t] = sigma1(W[t-2]) + W[t-7] + sigma0(W[t-15]) + W[t-16]
```

All additions are modulo 2^32 (overflow wraps around). This expansion creates the avalanche effect: a single bit change in the input propagates through all 64 schedule words.

---

## Step 6: Compression Function

For each block, initialize 8 working variables from the current hash state:

```
a = H0, b = H1, c = H2, d = H3
e = H4, f = H5, g = H6, h = H7
```

Then perform 64 rounds. Each round computes:

```
T1 = h + Sigma1(e) + Ch(e, f, g) + K[t] + W[t]
T2 = Sigma0(a) + Maj(a, b, c)

h = g
g = f
f = e
e = d + T1
d = c
c = b
b = a
a = T1 + T2
```

All additions are modulo 2^32.

After 64 rounds, add the working variables back to the hash state:

```
H0 = H0 + a
H1 = H1 + b
H2 = H2 + c
H3 = H3 + d
H4 = H4 + e
H5 = H5 + f
H6 = H6 + g
H7 = H7 + h
```

---

## Step 7: Produce the Final Hash

After processing all blocks, the 256-bit hash is:

```
hash = H0 || H1 || H2 || H3 || H4 || H5 || H6 || H7
```

Each H value is output as 4 bytes in big-endian order, producing 32 bytes (64 hex characters).

---

## Why SHA-256 Is Secure

1. **No known collisions**: Despite extensive research since 2001, no one has found two inputs with the same SHA-256 hash.

2. **Avalanche effect**: Changing a single bit in the input changes approximately 50% of the output bits.

3. **Preimage resistance**: Given a hash, finding any input that produces it requires approximately 2^256 operations (computationally infeasible with any foreseeable technology).

4. **Second preimage resistance**: Given an input, finding a different input with the same hash requires approximately 2^256 operations.

5. **Mathematical depth**: The combination of nonlinear functions (Ch, Maj), rotations, shifts, and additions creates thorough mixing that resists all known attack strategies.

## Applications

### Bitcoin Mining

Bitcoin uses double SHA-256 (SHA-256 applied twice) for proof-of-work. Miners must find a block header whose double-hash starts with a certain number of zero bits.

### TLS/HTTPS

SHA-256 is used in TLS for certificate fingerprints, message authentication (HMAC-SHA256), and key derivation.

### Digital Certificates

X.509 certificates used across the internet rely on SHA-256 for their signatures, replacing the broken SHA-1.

### File Integrity

Verifying downloads and software packages have not been tampered with using sha256sum.

### Git

Git is migrating from SHA-1 to SHA-256 for identifying commits, trees, and blobs.

## Comparison: MD5 vs SHA-1 vs SHA-256

| Property | MD5 | SHA-1 | SHA-256 |
|---|---|---|---|
| Output size | 128 bits | 160 bits | 256 bits |
| Block size | 512 bits | 512 bits | 512 bits |
| Rounds | 64 (4x16) | 80 | 64 |
| State words | 4 x 32-bit | 5 x 32-bit | 8 x 32-bit |
| Byte order | Little-endian | Big-endian | Big-endian |
| Security | Broken (2004) | Broken (2017) | Secure |
| Speed | Fastest | Medium | Slower |

SHA-1 was broken by Google in 2017 (SHAttered attack). SHA-256 remains the recommended minimum for all security applications.

## Summary

```
Input:   Any-length message
Output:  256-bit hash (64 hex characters)

Process:
  1. Pad message to multiple of 512 bits (big-endian length)
  2. Initialize 8 state words from sqrt of first 8 primes
  3. For each 512-bit block:
     a. Expand 16 words -> 64 words (message schedule)
        Uses sigma0 and sigma1 functions
     b. 64 rounds of compression
        Uses Ch, Maj, Sigma0, Sigma1 functions
        Plus round constants from cbrt of first 64 primes
     c. Add round results to running state
  4. Output = concatenation of 8 state words (big-endian)

Key constants:
  - Initial hash: fractional parts of sqrt(first 8 primes)
  - Round constants: fractional parts of cbrt(first 64 primes)

6 logical functions: Ch, Maj, Sigma0, Sigma1, sigma0, sigma1

Status: SECURE. Industry standard.
```
